# 代理帧关联实验：源时间映射 vs 内容锚点

本文件记录在仓库内完成的对照实验。目标是回答一个具体问题：**代理在重新编码
（删帧、时码/帧率变化、冻结帧）之后，剪辑标记（clip 的源帧入出点）怎样保持
原来的含义？** 两套小型适配原型都已实现，并接到了动画预演现有的查帧入口
`proxyworkstation/ui/preview.py`，在与测试套件相同的合成镜头上实测。原型不替换
V1 项目格式（SQLite schema 与 `FrameMap` 原样保留），只作为可切换的关联策略存在。

* 原型代码：`proxyworkstation/experimental/fingerprint.py`、`resolvers.py`
* 实验驱动（可重跑）：`scripts/proxy_association_experiment.py`
* 残差数据（可由代码重新取得的快照）：
  `experiments/proxy_association/association_report.json`
* 测试：`tests/test_experimental.py`、`tests/test_experiment_regression.py`
* 生产接点：`FramePreview.load_media(..., resolver=...)` 与主窗口的
  “Frame association”下拉框（`v1-frame-map / source-time-map / content-anchor`）

复现实验数据：

```bash
source tools/env.sh
python3 -I scripts/proxy_association_experiment.py experiments/proxy_association
```

## 1. 两种方案怎样把代理帧关联回源帧

### 方案 A：按源时间映射（`TimeMappingResolver`）

关联关系来自**变换履历（provenance）**：源帧率、代理帧率、帧数、起始偏移，套用
算术公式

```
source_frame = round(proxy_frame * source_fps / proxy_fps) + start_offset
```

* 查询成本 O(1)，不需要解码任何媒体，索引字节数为 0。
* 精度完全取决于履历是否真实。实验里区分两种姿态：
  * `time_map_declared`：只信代理自报参数（模拟外部转码器没记录删帧的情形）；
  * `time_map_informed`：掌握精确变换日志（真实 `start_offset` + 实际覆盖到的源帧
    集合 `coverage`），覆盖区间外的映射显式报 `ambiguous`，而不是静默给号。

### 方案 B：按内容锚点（`ContentAnchorResolver`）

把每个代理帧解码成 16×16 灰度指纹，与原片指纹表做平均绝对差（MAE，与现有
代理验证同口径）匹配。

* 全索引（`anchor_step=1`）：源片每帧都是锚点，逐帧独立匹配，带唯一性检查。
* 稀疏锚点（`anchor_step=2/4/8`）：只保留部分源帧做锚点；先找可信锚点命中并做
  单调化（重编码不会倒放），再在相邻命中锚点之间线性插值，首尾外推显式标
  `weak_match`。这是索引成本/精度的旋钮。
* 三档置信度：`exact`（d ≤ 3 的唯一命中）、`weak_match`（只剩最近邻幸存帧）、
  `ambiguous`（两个候选近等距，冻结/重复内容）、`unmatched`（超过硬上限 18）。

## 2. 代理重新编码后，剪辑标记怎样保持含义

标记（入/出点）本质是“**这个画面瞬间**”，不是“第几个文件帧”。重编码后保持含义
靠 `relocate_marker()`：在代理坐标系里重新定位标记所指的画面，并返回**重定位
残差**与显式状态，而不是假定帧号不变。

* 幸存帧：内容锚点直接找回承载同一画面的代理帧，残差 0。
* 被删帧：标记所指画面在代理里不存在。方案 B 不报假答案——距离超过可信阈值即
  `unrelocatable`，或仅给出 `weak_match` 的最近邻并声明标记本身已丢失。
* 冻结/重复：同一画面在代理里出现多次，像素无法唯一定位，报 `ambiguous` 并列出
  候选，交给剪辑师裁决，而不是随机选一个。
* 时间映射方案：只有在掌握精确变换日志时才能反解标记；只信自报参数时，删帧会
  让公式整体平移，标记“看起来有效”但含义已经错位（最危险的失败模式）。

## 3. 实验设置与“无法可靠对应”的构造

所有变体都从一份**显式源帧索引列表**构造：代理帧 `p` 描绘源帧
`source_indices[p]`，这就是测量残差所用的 ground truth，而非事后假设。24 帧
SHOT_A（960×540，带烧录帧号和移动色带，保证每帧像素可区分）：

| 变体 | 构造 | 破坏的假设 |
| --- | --- | --- |
| `reencode_healthy` | 纯降分辨率重编码，时间保持 | 无（对照组） |
| `head_trim` | 删除开头 4 帧 | 零偏移 / 时码连续 |
| `mid_drop` | 删除中间第 8–11 帧 | 帧数一一对应、时间连续 |
| `rate_convert` | 24→30fps 最近帧重采样 | 同帧率；产生重复帧 |
| `frozen_run` | 第 10–13 帧冻结为第 9 帧画面 | 帧内容唯一 |

标记取 `[0,3,6,9,11,13,17,23]`，刻意落在被删/被冻结区间内。

## 4. 实测结果（标记重定位残差，快照见 JSON）

### 4.1 逐帧前向关联残差（代理帧 → 源帧，绝对值，帧）

| 变体 | 方案 | 最大残差 | 平均残差 | 不可靠帧数 |
| --- | --- | --- | --- | --- |
| healthy | 全部方案 | 0 | 0.0 | 0 |
| head_trim | time_map（自报） | **4** | 4.0 | 0（静默错位） |
| head_trim | time_map（精确日志） | 0 | 0.0 | 0 |
| head_trim | content step1 | 0 | 0.0 | 0 |
| mid_drop | time_map（自报） | 4 | 2.4 | 0（静默错位） |
| mid_drop | time_map（精确日志） | 6 | 2.4 | 4（删除段报歧义） |
| mid_drop | content step1 | **0** | 0.0 | 0 |
| mid_drop | content step2/4/8 | 2 / 3 / 2 | 0.1–0.6 | 0 |
| rate_convert | time_map（两种） | 0 | 0.0 | 0 |
| rate_convert | content step1 | 0 | 0.0 | 0（重复帧标记报歧义） |
| frozen_run | time_map（自报） | 4 | 0.42 | 0（静默错位） |
| frozen_run | time_map（精确日志） | 5 | 0.42 | 4 |
| frozen_run | content step1 | 0 | 0.0 | 0（冻结标记报歧义/不可重定位） |

要点：自报参数的时间映射在 head_trim 上**每一帧都恰好偏移 4**且状态全是
`exact`——它自信地给出错误答案。内容锚点在所有删帧变体上对幸存帧残差为 0，
并把无法对应的区间显式标出。

### 4.2 标记重定位状态（content step1，8 个标记）

| 变体 | exact | ambiguous | weak_match | unrelocatable |
| --- | --- | --- | --- | --- |
| healthy | 8 | 0 | 0 | 0 |
| head_trim | 6 | 0 | 1（帧3） | 1（帧0） |
| mid_drop | 6 | 0 | 1（帧11） | 1（帧9） |
| rate_convert | 7 | 1（帧6，重采样重复） | 0 | 0 |
| frozen_run | 6 | 1（帧9，冻结） | 1（帧13） | 1（帧11） |

`ambiguous`/`weak_match`/`unrelocatable` 正是“无法可靠对应”的三类区间，系统
拒绝猜测，把裁决权留给剪辑师。

### 4.3 索引成本（24 源帧 / 20 代理帧的 mid_drop）

| 方案 | 解码帧数 | 索引字节 | 锚点表 | 查询成本 | 建索引耗时 |
| --- | --- | --- | --- | --- | --- |
| time_map | 0 | 0 B | — | O(1) 算术 | 0 |
| content step1 | 44 | 11264 B | 6144 B（24 锚点） | O(24) 距离/帧 | ~0.14 s |
| content step2 | 44 | 11264 B | 3328 B（13 锚点） | O(13) | ~0 s（命中缓存） |
| content step4 | 44 | 11264 B | 1792 B（7 锚点） | O(7) | ~0 s |
| content step8 | 44 | 11264 B | 1024 B（4 锚点） | O(4) | ~0 s |

内容锚点必须把源片和代理各完整解码一遍（线性于总帧数），指纹表随帧数线性增长；
稀疏锚点只缩小查询表和单次查询距离量，**解码成本不变**（指纹全量计算后抽锚点）。
时间映射零解码、零存储，但把正确性全部押在履历上。

## 5. 决策

1. **V1 主路径维持时间保持契约 + 时间映射**：健康代理上两方案都零残差，而时间
   映射零索引成本、可纯算术往返，没有理由为常规降分辨率代理引入全帧解码开销。
2. **把内容锚点作为“非时间保持/来源不明代理”的受控回退**，仅在检测到删帧、帧率
   变化或外部转码器无法提供可信变换日志时启用；默认全索引（step1），长镜头可用
   step4 把查询表压到约 1/4，代价是稀疏区约 ±2 帧的有界插值误差。
3. **任何方案都不得对无法可靠对应的区间静默给号**。删除段（无此画面）报
   `unrelocatable`/`weak_match`，冻结/重复段（画面不唯一）报 `ambiguous`。这是
   内容锚点相对自报时间映射的根本优势：后者会带着 `exact` 状态整体错位。
4. **精度**：内容锚点在本实验全部幸存帧上残差 0；时间映射仅在持精确日志时达到
   同精度，持自报参数时 head_trim 最大残差 4、mid_drop/frozen 最大残差 4–6。
5. **索引成本**：时间映射 O(1)/0 字节；内容锚点 O(源帧+代理帧) 解码 + 每帧
   O(锚点数) 距离。24+20 帧的小镜头建索引约 0.14 s、11 KB，量级可接受，长片需
   稀疏锚点或分段建库。
6. **无法可靠对应的区间**（两方案都不能给精确答案，必须显式上报）：
   * 被删帧本身——画面不存在，只能给最近邻幸存帧并声明标记丢失；
   * 冻结/重采样重复段——画面存在但位置不唯一；
   * 稀疏锚点首尾外推区——只有单侧锚点约束；
   * 超出硬距离上限的内容（代理来自不同源或严重损坏）——`unmatched`。

## 6. 代理身份方案：具体方案比较与待验假设

身份回答“这个代理文件是不是同一来源的那个代理”。现有 V1 用**全文件 SHA-256**
作主键。重编码会改变字节，因此需要区分“文件身份”和“来源身份”。

| 方案 | 做法 | 优点 | 弱点 |
| --- | --- | --- | --- |
| F1 全文件哈希（现状） | SHA-256 整个代理文件 | 实现简单、抗篡改、与重定位闸门复用 | 任何重编码都换身份，无法表达“同一来源的新版代理” |
| F2 来源哈希 + 变换参数指纹 | 主键=源内容哈希；代理版本键=（源哈希, 高度, CRF, preset, fps, 帧数, FrameMap） | 重编码生成可预期的新版本，天然带时间映射履历 | 参数相同不代表内容正确；仍需内容闸门；删帧若未如实记录会污染履历 |
| F3 内容锚点派生身份 | 用锚点指纹集合（或其哈希）证明代理与源的画面对应 | 不依赖自报参数，直接支撑第 4 节的健壮关联 | 建库最贵；冻结/重复帧天然不具区分度，不能单独作唯一身份 |

实验支撑的取向：**F2 作主版本身份 + F3 作验证/回退关联**，F1 继续用于文件完整性
与重定位。F3 的指纹不适合单独当主键（冻结段会碰撞），但适合在 F2 履历不可信时
证明画面级对应。

### 待验假设（单列，尚未在本实验中证明，需要后续专门实验）

* H1：16×16 灰度 MAE 阈值（可信 3 / 硬上限 18）来自本合成镜头；真实动画素材（噪点、
  渐变、纹理）的分布可能漂移，需在真实片库上重新标定阈值。
* H2：指纹对 H.264 不同 CRF/preset 稳健——本实验固定 CRF16/28，未扫描编码参数面。
* H3：单调化先验“重编码不倒放”成立的前提是单一连续镜头；跨镜头拼接/倒放特效会
  违反该先验，需按镜头分段建索引。
* H4：稀疏锚点误差上界 ≈ anchor_step/2 仅在时间连续区成立；删帧跳变处的插值误差
  已观测到等于完整 step（mid_drop step4 最大残差 3）。
* H5：建索引耗时与帧数线性；本实验只测了 18–30 帧小镜头，长片的解码耗时、内存与
  缓存失效策略未测。
* H6：F2 的参数指纹能区分“同参数不同内容”的代理——需构造同参数诱饵代理验证。
* H7：冻结/重复内容在真实素材中的占比未知，决定 `ambiguous` 在生产中出现的频率。

## 7. 生产接点（已实际接通，非纯架构描述）

* `FramePreview` 新增 `resolver=` 参数；提供解析器时，查帧标签直接显示
  `scheme:status` 与距离（如 `content_anchor:exact d=0.40`），歧义/未匹配在界面
  可见。不传解析器时走原 V1 `frame_map`，行为不变（由测试锁定）。
* 主窗口新增 “Frame association” 下拉框，三项均可在真实预览中切换；内容锚点的
  指纹缓存落在代理目录下的 `.fingerprint_cache/`，不写 V1 数据库。
* UI 接点由 `tests/test_experimental.py` 中两个 Qt offscreen 测试覆盖，确认两种
  实验方案都真正驱动了查帧入口并返回正确源帧。
